# Languages (i18n)

The interface is available in **English**, **ଓଡ଼ିଆ (Odia)** and **हिन्दी (Hindi)**,
using `i18next` and `react-i18next`. The language is changed from the globe
button in the top bar (or under Preferences, or on the sign-in page), applies
without reloading, and is remembered.

## Files

```text
client/src/i18n/
├── index.js                 the list of languages, and i18next's setup
└── locales/
    ├── en/common.json
    ├── od/common.json
    └── hi/common.json
```

No translation is written inside a component. Components ask for a key:

```jsx
const { t } = useTranslation();
<Button>{t('actions.save')}</Button>
t('table.selected', { count: 3 })     // plural forms: selected_one / selected_other
t('login.subtitle', { name })         // {{name}} is filled in
```

## Adding a language

1. Copy `locales/en/common.json` to `locales/<id>/common.json` and translate
   the values (keep the keys and the `{{placeholders}}`).
2. In `i18n/index.js`, import it and add an entry to `LANGUAGES`:
   `{ id, name, locale, resources }` - `name` is the language's own name for
   itself; `locale` is what dates and numbers are formatted with.

`theme.test.js` fails if a language is missing a key that English has, has an
empty value, or lost a placeholder.

## What is translated

| Translated | Not translated |
| ---------- | -------------- |
| Navigation, top bar, search and command palette, user menu, preferences | Business data from the API: company names, people, products, **status and priority names** (an administrator names those) |
| Sign-in page, error pages, empty / loading / error states | Record numbers, SKUs, ids |
| Table toolbar, paging, filters, bulk actions, quick view | API and database field names |
| Page titles, subtitles and "New …" buttons of every list page | Messages returned by the API (they are shown as the API wrote them) |
| Column headers and filter labels of the twelve list pages | |
| Dashboard chrome (title, customize, sizes, full screen, download) | |

**Not yet translated** (still English in every language): the inside of the
detail pages and forms, dialogs of the individual modules, the settings
screens, the reports screen, the audit log screen, the dashboard's metric and
chart titles, and validation messages inside module forms. To translate one,
replace its text with `t('…')` and add the key to all three files - the test
keeps the three in step.

## Dates, numbers and relative time

Formatting follows the language (`utils/format.js`, `configureLocale`):
English uses the browser's own conventions; Odia uses `or-IN`; Hindi uses
`hi-IN`. That covers dates, times, amounts, compact numbers ("10.6M") and
relative time (`formatRelative`). The administrator's date format and time
zone (Application settings → CRM) still apply on top.

Data stays language-neutral: the API stores and returns the same values
whatever language the interface is in.

## A note on the translations

The Odia and Hindi text was written for this release and has not been reviewed
by a native speaker. Wording can be changed freely in the two JSON files; no
code depends on it.
